# Datasets

Committed derivatives live under `datasets/`. Raw OSF and Stanford downloads
are regenerated by `scripts/prep_*.py` into `.cache/` and are gitignored.
Canonical checksums: [`SHA256SUMS`](SHA256SUMS). Default CI paths:
[`datasets/CI_FIXTURES.txt`](datasets/CI_FIXTURES.txt).

Sibling packages should **pin a commit or tag** of this public repository
and verify SHA256 after fetch. See the README for submodule, sparse-clone,
and `scripts/fetch_fixtures.py` options. Do not vendor copies, and do not
add HCP or other restricted participant data.

### Classic 641 × 7 selection rule

Columns (OSF names, same order as tetrad-rs `tests/data/boston_data_raw.csv`):

`alcohol_bev`, `TIB`, `TST`, `PANAS_PA`, `PANAS_NA`, `worry_scale`, `PHQ9`

PANAS_PA/NA, worry_scale, and PHQ9 are OSF-derived sums and exist only on
the Full instrument (`redcap_repeat_instrument == covid19`).

Rule, which reconstructs the classic file **byte-for-byte**:

1. Drop rows missing any of the 7 columns.
2. Effective date = `ref_date` when present, otherwise the date of
   `redcap_timestamp`. One Full-survey row (`unique_id` `3839L`, subject 130)
   has a blank `ref_date` and a 2020-04-12 timestamp.
3. Keep subjects with **≥ 31** complete rows whose effective date is
   **< 2020-07-01**. That cutoff selects exactly these 20 subjects
   (31–34 rows each): 24, 41, 46, 53, 60, 79, 86, 113, 128, 130, 132, 141,
   146, 152, 162, 199, 251, 286, 290, 350. (≥ 30 would add more subjects;
   ≥ 32 would drop some.)
4. Emit those 641 rows in **original OSF file order**.

Every row is a Full survey from the first collection window
(2020-03-21 through 2020-06-30).

### Cross-subject lag caveat

tetrad-rs historically builds a 640 × 14 matrix by pairing consecutive rows
of the **pooled** 641-row stack (`lag_consecutive`, suffix `_lag`). That
shift crosses a subject boundary **19 times**. Within a subject, “lag” is
the previous Full survey (typically 2–4 days earlier), not the previous
calendar day.

The classic `boston_data_raw.csv` is unchanged so existing CI edge lists
keep matching. For new work, prefer
`boston_data_lagged_within_subject.csv`: same 7 variables plus `*_lag`,
lagged **inside each subject**, first row of each subject dropped
(641 − 20 = 621 rows). Column order matches tetrad-rs: current variables,
then `*_lag`. `boston_prior.txt` still applies (same names).

### Single-subject Set A (10 variables)

Asked on both Full and Short surveys:

`TIB`, `TST`, `sleepdiary_sleeplatency`, `sleepdiary_wakes`,
`night_awakening_time`, `sleepdiary_naptime`, `socialize_min`,
`people_contact`, `alcohol_bev`, `stress`

Subject **132** is the primary single-subject case (142 complete rows,
max \|r\| ≈ 0.74 for TIB–TST, seven collection windows 2020-03 to 2021-11).
~90% of consecutive surveys are one day apart; 2–3 gaps of ~100 days
separate collection waves.

## MyConnectome (Poldrack lab)

License: **CC0 / ODC-PDDL 1.0**. Cite Poldrack et al. (2015) and Laumann et
al. (2015); see NOTICE. Timeseries from
`combined_data_scrubbed/sub066.txt`; labels from `parcel_data.txt`.

Each session is 518 timepoints × 630 parcels (616 individual-specific
cortical + 14 subcortical), TR = 1.16 s. Session **066** has the lowest
mean FD (0.0885) and zero censored frames. Values are written at 6 decimal
places.

`P###_subcort_{L,R}`.

### 50-ROI subset (CI)

Open replacement for a non-redistributable 520 × 50 HCP-style series.
**HCP data are not in this repository.**

1. Left hemisphere only.
2. Drop Zero-network parcels and subcortical (`network_norm` in `{Zero, subcort}`).
3. Take the **lowest parcel IDs** in each remaining network: **5** from DMN
   and Somatomotor, **4** from every other assigned network (50 total).
4. Emit columns in increasing parcel-ID order.

max \|r\| ≈ 0.87. This list matches `myconnectome_roi50.txt` exactly.

### 379-ROI subset (CI large, full rank)

Open replacement for a non-redistributable 520 × 379 Glasser-style series.
T = 518 > p = 379, so the sample covariance is full rank (rank 379).

1. Both hemispheres.
2. Eligible = cortical parcels whose normalized network is not `Zero` and
   not `subcort` (554 parcels, 12 networks). `Frontoparietal 2` in
   `parcel_data.txt` is normalized to `Frontoparietal_2`.
3. Allocate 379 slots with the **largest-remainder** (Hamilton) method,
   proportional to each network’s eligible count. Remainder ties break by
   network name (ASCII).
4. Inside a network, take **evenly spaced parcel IDs** with inclusive
   endpoints: index `round(i * (n − 1) / (k − 1))` for `i = 0..k−1`.
5. Emit columns in increasing parcel-ID order.

### 630-ROI matrix (non-CI)

`datasets/myconnectome/large/` is **outside the CI fixture set**. T = 518
< p = 630, so the covariance has rank 518 and is singular. Fisher Z with
small conditioning sets can still run; SEM-BIC and large conditioning sets
will hit singular matrices. Default tests should use the 379-ROI file.

Session 070 (FD 0.0894, also 0 censored frames) can be rebuilt with
`python3 scripts/prep_myconnectome.py --session sub070` but is not
committed.

## How sibling packages should consume fixtures

| Use case | Path | License note |
|----------|------|----------------|
| Classic Boston PC/FGES/GFCI CI | `boston_data_raw.csv` + `boston_prior.txt`; lag in-process if you must match historical 640 × 14 edges | CC-BY 4.0 attribution required |
| New Boston lag work | `boston_data_lagged_within_subject.csv` + `boston_prior.txt` | CC-BY 4.0 |
| Single-subject Boston | `boston_sub132_allsurveys_10v.csv` | CC-BY 4.0 |
| Small rsfMRI | `myconnectome_sub066_518x50.csv` | CC0 / PDDL |
| Large rsfMRI CI | `myconnectome_sub066_518x379.csv` | CC0 / PDDL |
| Optional full parcellation | `large/myconnectome_sub066_518x630.csv` | CC0 / PDDL; not CI |

Pin `<owner/repo>@<commit>` of this public repository. After copy or submodule
update, `sha256sum -c SHA256SUMS`. tetrad-rs, ezcausal, and opencausal
should drop vendored Boston / synthetic-HCP substitutes in favor of these
paths.
